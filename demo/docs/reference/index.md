# 设计约定

这一页解释插件为什么长这样。如果你打算改它的样式，或者只是想确认它不会和你的
主题打架，看这里就够了。

## 它长在主题上，而不是长在主题旁边

区块**从不写死颜色**。所有颜色要么直接取 Material 的语义变量，要么由一个色相推导：

| 用途 | 来源 |
| --- | --- |
| 文字 | `--md-default-fg-color` |
| 次要文字 | `--md-default-fg-color--light` |
| 极浅的底（标签、圆点） | `--md-default-fg-color--lightest` |
| 表面 | `--md-default-bg-color` |
| 强调色 | `--md-primary-fg-color`、`--md-accent-fg-color` |
| 正文链接 | `--md-typeset-a-color` |
| 阴影 | `--md-shadow-z1` / `--md-shadow-z2` 的同型写法 |

所以：自定义 `primary` / `accent`、切换 `slate` 深色方案、读者打开高对比度，
都不需要插件做任何事。

区块之间靠 `theme:` 区分。一个主题**只声明一个色相**：

```css
.md-home--theme-cyan { --md-home-hue: 187; }
```

强调色、浅底、描边、高光都由这一个值推导。派生值声明在每个可能带主题的元素上，
所以卡片的 `theme:` 只影响这张卡片，而没写 `theme:` 的卡片会继承整块的颜色，
不会退回默认值。

## 它重新声明了主题的字号

区块的 HTML 落在 `.md-content__inner` 里，那正是 `.md-typeset`，所以 Material 的
元素选择器会命中区块内部的标签。必须重新声明的几处：

| Material 的规则 | 后果 | 处理 |
| --- | --- | --- |
| `[dir="ltr"] .md-typeset ul` 与 `ul li` 的 `margin-left` | 卡片墙每层多出 10px / 20px 缩进 | 在 `.md-home` 内部重设为 0 |
| `.md-typeset h1..h6` 用 `rem` 定字号 | 卡片标题变成 32px | 在 `.md-home` 内部用 `em` 重设 |
| `.md-icon svg { height: 1.2rem }` | 图标 24px，比文字还大 | 重设为 `1em` |
| `.md-typeset table/pre/code` 用 `rem` | 在区块里偏大 | 统一为 `1em` |

这些重设都写成 `.md-typeset .md-home ...`，靠**选择器权重**取胜，而不是靠样式表
加载顺序——后者是不可靠的。

## 可以覆盖的变量

如果你只想微调，不必重写选择器，改这几个变量就够：

```css
:root {
  --md-home-hue: 231;           /* 默认色相（indigo） */
  --md-home-radius: 0.6em;      /* 圆角 */
  --md-home-radius-sm: 0.35em;  /* 小圆角：图标底、图片 */
  --md-home-gap: 0.9em;         /* 栅格间距 */
  --md-home-pad: 1.2em;         /* 卡片内边距 */
  --md-home-min: 13em;          /* 栅格项最小宽度 */
  --md-home-icon-size: 1em;     /* 图标尺寸的基准 */
}
```

也可以写在 `mkdocs.yml` 里，插件会把它们注入到 `<head>` 的最末尾：

```yaml
plugins:
  - homepage:
      css_vars:
        --md-home-radius: 0.9em
        --md-home-gap: 1.1em
```

这些默认值声明在 `:root`，不是为了好看：**只有 `:root` 上的值会被继承下去**。
声明在 `.md-home` 上的自定义属性，只会作用于那个元素及其子树，于是两件事会静默地失效——

- 阅读器把 `css_vars` 注入到 `:root`，而**匹配到元素本身的声明会赢过继承来的值**，
  所以写在 `.md-home` 上的默认值把用户的覆盖全部盖掉了；
- 灯箱是挂在 `<body>` 下的，不在 `.md-home` 里，读不到里面任何变量。
  `border-radius: var(--md-home-radius-sm)` 在那里是无效值，`box-shadow` 退化成 `none`：
  放大的图片是直角、没有阴影，控制台不报错，也没有任何断言会失败。

由色相推导出来的那半张调色板（强调色、浅底、阴影）仍然声明在每个可能带主题的元素上，
因为它必须跟着 `theme:` 重算。

## 间距是一条阶梯，不是一堆数字

区块内部与区块之间的间距只有六个档位，每档约为上一档的两倍：

| 变量 | 值 | 用途 |
| --- | --- | --- |
| `--md-home-space-1` | `0.4em` | 标题与它自己的说明 |
| `--md-home-space-2` | `0.6em` | 关系紧密的几项 |
| `--md-home-space-3` | `0.9em` | 面板内部的分组，也是默认栅格间距 |
| `--md-home-space-4` | `1.2em` | 一个区块内部的几块内容之间 |
| `--md-home-space-5` | `1.6em` | 区块标题与它的内容之间 |
| `--md-home-space-6` | `2.5em` | 区块与区块之间 |

`--md-home-gap` / `--md-home-pad` / `--md-home-section-gap` 直接取其中一档，所以它们不会各自跑偏。
两条硬规则：

- **面板的内边距必须大于面板之间的间距**（`pad` > `gap`）。卡片看起来拥挤，
  往往不是因为它小，而是因为一张卡内部的空间比两张卡之间的空间还大。
- **每两个区块之间的距离必须相等**。这条曾经不成立：
  `.md-home:first-child + .md-home { margin-block-start: 0 }` 把*第二个*区块的入场间距
  也清掉了，于是首屏与品牌墙之间只有 26px，而其余每一对都是 40px。

## 卡片被按下时，边缘会发光

卡片的状态是有层次的，不是四个各自为政的 `box-shadow`：

| 状态 | 边缘 | 发光 | 触发 |
| --- | --- | --- | --- |
| 静止 | 一根描边 | — | — |
| 悬停 | 描边加深 | 只有投影抬高 | `:hover`，且只在真的有悬停能力的设备上 |
| 按下 / 键盘聚焦 | 强调色描边 | 描边 + 外溢光晕 + 内洗 | `:active` 或 `:focus-visible` |

几个刻意的选择：

- **`:active` 没有被包在 `@media (hover: hover)` 里。** 那是一条关于*能力*的查询，
  写成那样就是一个手机永远看不到的按下反馈——而手指没有悬停，按下是它唯一的反馈。
  同理，悬停发光只在真的有悬停能力时才出现，否则点一下就会“粘”住。
- **`:active` 与 `:focus-visible` 共用同一条规则。** 拆成两条就会各自漂移；
  合并之后，鼠标与键盘拿到的一定是同一种光。
- **光是算出来的，不是写死的。** 三层都取当前色相的强调色，
  所以 `theme: cyan` 的卡片按下时发青光，切换深色方案时也不会突然变成另一张卡。
- **权重是被验证过的，不是猜的。** 这条规则是 (0,4,0)，必须压过 `filled` / `plain` 里的
  `box-shadow: none`；而那条为了保留 `plain` 风格而写的悬停例外（0,5,0）会比它更高，
  所以例外写成 `:hover:not(:active):not(:focus-visible)`——它只豁免悬停，不豁免按下。
  这个细节是先算出来再改的：一开始漏了 `:not()`，被按下的 `plain` 卡片就仍然没有边缘。

## 同一个形状，同一个高度

引用卡、品牌墙的格子、链接卡和卡片墙的卡片是同一种东西：圆角 + 一根描边。
它们由**一条规则**统一拿到投影，否则引用卡会比旁边的卡片墙明显“平”一层。
文字面板与折叠块刻意不在其中——它们是内容容器，Material 自己的 admonition 也是平的。

图标气泡（卡片图标、特性图标、步骤序号）同理：三种气泡共用同一条内描边变量，
否则它们看上去就像是三次各自为政的尝试。

## 栅格没有断点

`columns: 3` 的含义是「最多三列」：

```css
grid-template-columns: repeat(auto-fit, minmax(min(100%, max(var(--md-home-min), <按列数算出的最小宽度>)), 1fr));
```

容器装得下就三列，装不下自动变两列、一列。因此**没有任何媒体查询需要维护**，
也不会出现某个断点忘了改的情况。

`align: center` 要额外处理一下：`text-align: center` 只能居中**文字**，它不会居中
一个竖排 flex 容器自己的项（结果是标题居中了，图标还在左边）。所以当区块是居中对齐
时，插件的样式表会把这几个 flex 容器的交叉轴一并居中。

## 装饰底纹

`hero` 与 `cta` 默认带一层 `aurora` 底纹，其余区块默认没有，需要时写 `pattern:`：

| 取值 | 效果 |
| --- | --- |
| `aurora` | 两团径向渐变的光晕，像极光 |
| `grid` | 渐隐的方格，像工程图纸 |
| `dots` | 渐隐的圆点阵 |
| `rays` | 从中心向外发散的射线 |
| `none` | 关掉（也可以写 `pattern: false`） |

底纹是一层 `::before`，颜色仍由当前色相与 `--md-default-bg-color` 混合得出，
所以浅色与深色方案下都是「比背景亮一点」或「暗一点」，不会突然变成一块白斑。
底纹始终 `pointer-events: none`，不会吃掉卡片的悬停。

## 标题字号是流体的

首屏与行动号召的大标题不写死字号，而是按视口宽度插值：

```css
font-size: clamp(1.85em, 1.25em + 1.9vw, 2.7em);
```

下限保证窄屏上不会比正文还小，上限保证宽屏上不会撑破行宽，中间部分随窗口平滑变化。

## 图标有两个集合

内置的图标是构建时**从主题源码里拷出来的 SVG 路径**，运行时不发请求、也不用图标字体：

| 集合 | 前缀 | 内容 |
| --- | --- | --- |
| Material Design Icons | 默认，或 `material/<名字>` | 界面上用的一般图标，约 58 个 |
| Simple Icons | `simple/<名字>` | 品牌标，约 30 个 |

两者用同一种写法：`icon: simple/github`、`icon: material/github`、`icon: github`。
写错名字会输出警告并列出可用名字。`homepage-logos` 区块默认查的是 Simple Icons，
因为 MDI 里几乎没有品牌标。

图标以 `currentColor` 单路径内联，外面套的是主题自己的 `.md-icon`，所以颜色由主题
决定、尺寸由变量 `--md-home-icon-size` 决定。后者是**变量间接**：组件改的是变量值，
而不是再写一条 `svg { width }` 声明，这样单个组件的尺寸不会被通用重置规则反过来盖掉。

## 脚本是渐进增强的

`homepage.js` 只做五件事：倾斜与高光、滚动揭示、画册翻页、数字累加、点击放大。

- 关闭脚本时：画册仍然可以横向滚动（原生 `overflow` + `scroll-snap`），
  按钮和圆点被样式表隐藏，滚动揭示的初始隐藏写在
  `@media (scripting: enabled)` 里，所以内容一直可见。
- 打开「减少动态效果」时：倾斜、揭示、计数、逐字动画全部让位。
- 兼容 Material 的即时导航：优先订阅 `document$`，每次导航重新绑定；`init()` 可以
  反复执行——拆解时会连「已绑定」标记一起清掉，否则第二遍会跳过刚被解绑的元素。

### 卡片倾斜什么时候回正

倾斜的角度与高光位置由鼠标指针决定，所以只要指针**不再指着这张卡片**，它就回正：

| 情况 | 行为 |
| --- | --- |
| 指针移出卡片 | 回正 |
| 指针移到卡片内部的图标 / 标题上 | 不回正（仍在卡片内） |
| 指针移出窗口、窗口失焦、标签页切到后台 | 回正 |
| 页面滚动，卡片仍在指针下 | **不回正**，而是按新的位置重算——高光始终对着指针真实所在的地方 |
| 页面滚动，卡片被移出指针范围 | 回正 |
| 键盘焦点离开卡片 | 回正 |

角度是高优先级写入，鼠标快速划过后离去时也不会留下残留——离开会**取消**尚未执行的
那一帧，而不是跟在它后面改值。这个竞态正是「有时不回正」的原因。

倾斜之外的那层“边缘发光”与它无关：那是 `:active` / `:focus-visible` 的纯 CSS 状态，
不依赖指针位置，也不会被上面的重算影响。

## 渲染安全

区块内容分两路，各自有明确的规则：

- **进入属性或文本节点的值**一律 HTML 转义。
- **允许写 Markdown 的值**（`title`、`desc`、正文区）交给站点自己的
  `markdown_extensions` 渲染。长出来的 HTML 以「暂存块」的形式插回文档，
  因此 MkDocs 的相对链接重写、`toc` 的锚点等 treeprocessor 都碰不到它。
- **进入 `style` 的值**（圆角、宽高比、栅格列数）经过白名单校验，只会生成
  合法长度；写不出第二个声明，也写不出 `;`。
- `href` / `src` 会拒绝 `javascript:`、`data:` 之类的协议。

`title` 这类单行字段只接受**行内** Markdown：如果渲染结果不是一个段落
（比如你写了 `# 标题`），它会退回成纯文本转义，而不会把一个块级元素塞进标题里。

### 区块里的链接与图片

区块的 HTML 是以「暂存块」的形式插回文档的，MkDocs 自己的相对链接重写碰不到它。所以
插件做了一件等价的事：**在渲染区块正文时，按 MkDocs 的同一套规则解析链接**。

于是区块里的写法和页面正文完全一致：

| 在 `guide/blocks.md` 里写 | 解析为 |
| --- | --- |
| `index.md` | `../`（`guide/` 下的兄弟页面） |
| `../index.md` | `../../`（站点根目录的首页） |
| `../assets/a.png` | `../../assets/a.png` |
| `/assets/a.png` | 原样保留（站点部署在子路径下时要当心） |
| `https://…` | 原样使用，并自动新窗口打开 |
| `#anchor` | 原样保留 |

指向不存在文件的 `.md` 链接会输出警告并原样保留，和其他写错的地方一样可见。测试套件里
有两条断言会遍历产物：一条确认所有 `<img src>` 都落到真实文件上，另一条确认没有任何
`.md` 形式的 `href` 漏到线上。

## 插件选项

| 选项 | 默认 | 说明 |
| --- | --- | --- |
| `assets` | `true` | 是否把样式表与脚本挂到站点 |
| `assets_dir` | `assets` | 它们在站点里的目录 |
| `tilt` | `true` | 是否启用卡片倾斜 |
| `tilt_strength` | `6` | 倾斜强度（度） |
| `reveal` | `auto` | `auto` 只让列表类区块错峰出现；也可以给固定值或 `off` |
| `lightbox` | `true` | 点击图片放大 |
| `count` | `true` | 数字滚动累加 |
| `markdown_extension` | `true` | 是否自动注册 Markdown 扩展 |
| `strict` | `false` | 区块写错时直接让构建失败 |
| `css_vars` | `{}` | 注入到 `:root` 的自定义属性 |

单独使用 Markdown 扩展（不装插件、换别的主题）时，写上完整路径即可：

```yaml
markdown_extensions:
  - mkdocs_homepage.extension:HomepageExtension
```
